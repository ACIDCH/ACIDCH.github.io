## “无约束”只是数学上的第一层简化

Unconstrained optimisation 说的是模型里暂时没有显式写出资源上限、需求下限或逻辑限制，并不是现实世界真的没有边界。

它最适合先回答一个基础问题：当一个决策变量自己变化时，目标函数会怎么变，最好的位置为什么出现在那里？

例如容量增加通常会带来两种相反力量：

```text
容量更大
→ 能承接更多业务
→ 价值上升

容量更大
→ 维护、拥堵、预留或低利用成本上升
→ 边际收益下降
```

当两股力量抵消时，就可能出现一个内部最优点。

## 用一个容量模型看清函数形状

设容量决策为 x，净价值函数为：

\[
V(x)=96x-0.08x^2-18000
\]

三部分的含义很直观：

```text
96x
→ 容量带来的线性价值

-0.08x²
→ 容量扩大后的拥堵或复杂度成本

-18000
→ 固定基础成本
```

如果只看 `96x`，容量越大越好；如果只看 `-0.08x²`，容量越大成本增长越快。两项放在一起，净价值先上升，之后会达到峰值，再开始下降。

这类函数比单纯的“最大化收入”更接近很多实际容量问题，因为它承认扩张到一定程度以后，额外容量不再免费。

## 一阶导数告诉当前还值不值得继续增加

对 V(x) 求导：

\[
V'(x)=96-0.16x
\]

一阶导数可以理解为当前点附近再增加一点容量，净价值大约会怎么变化。

当：

```text
V'(x) > 0
```

继续增加 x 还能提高目标值。

当：

```text
V'(x) < 0
```

再增加容量反而会让净价值下降。

内部最优点满足：

\[
V'(x)=0
\]

所以：

\[
96-0.16x=0
\]

得到：

\[
x^*=600
\]

这不是因为 600 看起来“居中”，而是因为在这个点上，额外容量带来的边际价值正好被额外成本抵消。

## 二阶导数用来判断这个驻点是什么

只有一阶导数等于 0，还不能立刻断定是最大值。

继续求二阶导数：

\[
V''(x)=-0.16
\]

它始终小于 0，说明函数整体向下弯，是一个 concave function。

因此 x=600 对应最大值，而不是最小值。

这一步在简单单变量问题里看起来很基础，但思路非常重要：

```text
一阶导数
→ 找可能的最优位置

二阶导数 / 函数形状
→ 判断这个位置到底是峰值还是谷值
```

## 最优值是多少，还要代回原函数

把 x=600 代回：

\[
V(600)=96(600)-0.08(600)^2-18000
\]

得到：

\[
V(600)=10800
\]

所以连续模型的最优容量是 600，净价值是 10,800。

这里最好养成一个习惯：即使求解器或微积分已经给出 x，也重新代回目标函数核对一次。优化结果应该能被独立复算，而不是只相信软件屏幕上的最终数字。

## “最优 600”不代表 599 或 601 都不好

很多优化结果最容易被误解的地方，就是把一个数学最优点当成不可偏离的指令。

比较三个容量：

\[
V(575)=10750
\]

\[
V(600)=10800
\]

\[
V(625)=10750
\]

575 和 625 都只比最优值低 50。

也就是说，从 600 偏离 25 个容量单位，净价值只下降：

\[
10800-10750=50
\]

如果 575 更容易匹配仓库面积，或者 625 能给未来需求留一点缓冲，那么这 50 的差距可能非常值得接受。

最优点告诉“理论上最好在哪里”，near-optimal 区域则告诉“现实中有多少选择空间”。

## 函数越平，最优点附近越有弹性

在峰值附近，如果函数很平，决策变量变化不少，目标值却变化很小。这意味着管理上有更大的操作空间。

反过来，如果函数峰值很尖，稍微偏离就付出很高代价，那么决策就需要更精确。

二阶导数在这里也有直觉：曲率绝对值越大，函数弯得越厉害；越接近 0，局部越平。

因此，二阶信息不仅用来判断最大还是最小，也能帮助理解最优点附近的敏感程度。

## 数学最优点可能不是可执行的离散选择

连续模型给出 x=600 很方便，但现实容量可能只能从几个方案中选：

```text
575
600
625
```

这时可以直接比较候选值，而不是假设所有连续容量都能购买。

如果候选方案变成：

```text
575
625
```

两个方案的净价值都是 10,750。模型此时不会替管理层区分它们，因为目标值完全相同。

这正好说明一个重要边界：优化模型只会根据已经写进目标函数和约束的内容做选择。如果 625 带来更高扩展能力，而 575 风险更低，这些因素需要被额外讨论或写进模型。

## 连续最优点落不到可选档位时，要重新比较而不是直接四舍五入

假设计算结果不是 600，而是 612.4，实际容量却只能按 25 为一档采购。最接近的两个候选可能是 600 和 625。

这时直接把 612.4 四舍五入到 600 并不严谨，因为目标函数在两侧不一定对称。正确做法很简单：把可执行候选分别代回目标函数，再比较它们的净价值。

```text
连续模型
→ 找出最有吸引力的区域

离散业务选择
→ 在真实可选方案中重新比较
```

如果离散规则本身很多，例如容量必须是设备台数的整数倍、还伴随固定启用成本，那么问题已经开始接近整数优化，不应继续把连续解当作最终答案。

## 可以给 near-optimal 区域设置一个可接受损失

“附近方案也不错”最好不要停留在感觉上。可以先定义一个业务可接受的损失，例如目标值最多比最优值低 1%。

当前最优值是 10,800，那么 1% 的容忍范围对应：

\[
10800\times0.99=10692
\]

只要某个容量方案的净价值不低于 10,692，就进入这一组 near-optimal 候选。之后可以再用模型没有表达的执行因素比较：场地、扩展空间、交付周期、风险缓冲或整数批量。

这样的做法把“数学最优”与“管理选择”分成两步，也避免为了一个很小的目标差异牺牲明显的执行便利。

## 网格搜索和求导并不冲突

对于单变量函数，可以用不同方式找最优：

```text
解析求导
→ 直接解 V'(x)=0

网格搜索
→ 在一组候选 x 上计算 V(x)

数值优化
→ 用算法迭代寻找更优点
```

解析解最清楚，但不是所有函数都能轻松求导或解方程。网格搜索非常适合做验证：即使已经知道 600 是最优，也可以在 500 到 700 之间逐点计算，看看函数是否确实在 600 附近达到峰值。

Python 示例：

```python

def value(x):
    return 96 * x - 0.08 * x**2 - 18000

candidates = range(500, 701, 5)
best_x = max(candidates, key=value)
print(best_x, value(best_x))
```

用不同方法得到同一个结论，比只依赖一种方法更容易发现编码或公式错误。

## 数值优化结果也需要看初值、范围和函数图形

当函数没有方便的解析解时，数值优化会更常见。但算法返回一个候选点以后，仍然要判断它是不是合理的最优点。

对于单变量问题，可以在候选点左右再取几个值：

```text
x* - 10
x*
x* + 10
```

如果中间值确实更好，结果才和局部峰值的直觉一致。更复杂、非凸的函数还可能有多个局部最优点，不同初始值可能走向不同位置。

因此，“求解器成功结束”不等于已经理解目标函数。图形、网格和多初值比较仍然是很有价值的验证工具。

## 多变量时，边际变化会变成偏导数

如果目标函数同时受两个决策变量影响：

\[
f(x_1,x_2)
\]

就需要分别考虑：

\[
\frac{\partial f}{\partial x_1},\qquad
\frac{\partial f}{\partial x_2}
\]

内部驻点通常满足所有一阶偏导都为 0。

多变量情形还需要考虑变量之间的交互和整体曲率。单变量里的“二阶导数”会扩展成 Hessian matrix。

不过管理直觉没有变：先看每个变量的边际收益什么时候消失，再看这个驻点是不是一个真正的峰值。

## 边界最优为什么也会出现

无约束优化常讲内部最优点，但实际函数不一定在内部达到最佳。

例如决策变量虽然没有写成正式约束，但现实上只考虑：

\[
0\le x\le500
\]

而原函数的峰值在 600，那么在允许的范围里，最佳选择会落在边界 x=500。

因此，求出驻点以后仍然要检查决策范围。一个超出实际可选区间的数学点，不是可执行答案。

如果一阶导数在整个允许区间都大于 0，最优点自然在上边界；如果一直小于 0，则会落到下边界。并不是每个优化问题都应该强行找到一个“导数等于 0”的内部解。

## 参数一变，最优点也可能跟着移动

当前模型中：

\[
V(x)=ax-bx^2-F
\]

内部最优满足：

\[
x^*=\frac{a}{2b}
\]

如果单位价值 a 上升，最优容量会变大；如果拥堵系数 b 上升，最优容量会变小。固定成本 F 会改变净价值水平，但不会改变这个简单模型里的内部最优 x。

这种关系非常适合做情景分析。比起只给出“最优 600”，更有用的是说明哪些参数变化会把最佳容量推向另一个区间。

还可以直接比较参数变化是否会让最优点跨过某个真实采购档位。例如最优容量从 612 变成 628，数学上只移动了 16，但实际采购决策可能从 625 档跳到 650 档。连续参数变化与离散业务动作之间经常存在这样的决策阈值。

## 一套更实用的分析顺序

面对一个无约束优化问题，可以按下面的顺序走：

1. 先画或计算目标函数，确认整体形状；
2. 用一阶导数找边际变化为 0 的位置；
3. 用二阶导数或函数图形判断峰值还是谷值；
4. 把候选点代回目标函数复算；
5. 检查决策变量的实际范围和离散限制；
6. 比较最优点附近几个可执行方案，并明确 near-optimal 容忍度；
7. 用网格或局部取值复核数值求解结果；
8. 改变关键参数，看最优点和真实决策档位是否稳定。

无约束优化真正值得带走的，不只是“导数等于 0”，而是学会把函数形状、边际价值和现实可执行方案放在一起看。
