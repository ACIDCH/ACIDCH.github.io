## 这篇笔记解决什么问题

数据分析真正困难的地方通常不是记住某一个函数，而是知道下一步应该做什么。拿到一张业务表以后，先检查变量还是先画图；出现偏态分布以后应该换统计量还是直接变换；模型在训练数据上表现很好，为什么换一批数据就明显变差；分类准确率已经很高，为什么业务部门仍然认为模型不好用。这些问题彼此相关，不能只靠零散代码回答。

这篇笔记把 R、数据可视化、数据整理、统计分析和预测算法放在同一条工作流里。前半部分建立数据分析所需的计算基础，后半部分重点放在统计推断和机器学习：如何把样本中的规律推广到总体，如何衡量估计的不确定性，如何建立回归和分类模型，如何控制过拟合，以及怎样用没有参与模型拟合的数据评价预测算法。

参考资料的核心教学思路是从真实问题出发，再引入解决问题所需的统计和计算工具。这里保留这一思路，但案例改成更贴近商业分析的数据：客户、订单、订阅、配送和需求，而不是逐段复刻参考资料中的课堂数据。

## 第一部分：R 是分析语言，不只是计算器

### 对象、向量和数据框

R 的基本思想是把数据和分析结果都保存为对象。一个对象可以是一组数、一个字符向量、一张数据表、一套模型参数，也可以是完整的拟合模型。

```r
monthly_demand <- c(108, 121, 117, 132, 128, 141)
mean(monthly_demand)
sd(monthly_demand)
```

向量是很多 R 操作的基础。与逐个处理数据相比，向量化表达通常更简洁，也更接近统计问题本身。

```r
monthly_demand > 125
monthly_demand[monthly_demand > 125]
```

实际分析更常见的数据结构是 data frame 或 tibble。每一行表示一个观察单位，每一列表示一个变量。这个“行是观察、列是变量”的结构也为后面的可视化、回归和机器学习提供统一接口。

```r
subscriptions <- tibble::tibble(
  customer_id = 1001:1006,
  tenure_months = c(4, 18, 9, 31, 7, 24),
  monthly_spend = c(59, 82, 65, 104, 52, 91),
  service_calls = c(5, 1, 3, 0, 6, 2),
  churned = c("Churn", "Stay", "Stay", "Stay", "Churn", "Stay")
)
```

这六行只用于让语法容易看清。真正进行重采样、交叉验证和模型比较时，需要使用规模足够、能够代表目标场景的建模数据，而不是把这张小表当成训练集。

比较值得建立的习惯，是随时确认对象的类型、长度、维度和缺失情况。

```r
class(subscriptions)
dim(subscriptions)
str(subscriptions)
summary(subscriptions)
```

### 索引和逻辑条件

R 中的逻辑向量可以直接用于筛选。下面先产生一组 TRUE/FALSE，再用它选出高消费客户。

```r
high_spend <- subscriptions$monthly_spend >= 80
subscriptions[high_spend, ]
```

遇到缺失值时要特别注意。比较运算可能返回 `NA`，而 `NA` 不是 FALSE。正式筛选前应先确认缺失值如何处理，不能默认把“未知”当成“不满足条件”。

### 函数、条件和重复任务

当同一种处理需要重复出现时，应优先考虑函数，而不是复制粘贴多段相似代码。

```r
coefficient_of_variation <- function(x) {
  sd(x, na.rm = TRUE) / mean(x, na.rm = TRUE)
}

coefficient_of_variation(monthly_demand)
```

条件判断适合把规则写清楚，例如给需求波动做一个简单分级。

```r
cv <- coefficient_of_variation(monthly_demand)

if (cv < 0.10) {
  "Low variability"
} else if (cv < 0.25) {
  "Moderate variability"
} else {
  "High variability"
}
```

分析脚本中最有价值的函数往往并不复杂。把“读入数据、清洗字段、计算指标、画图、训练模型”拆成小函数，可以让整个分析更容易检查和重跑。

### tidyverse 的价值在于一致的语法

`dplyr` 把常见数据处理任务组织成一组语义很清楚的动词：`filter()` 选行、`select()` 选列、`mutate()` 新建或修改变量、`summarise()` 计算汇总、`group_by()` 定义分组。

```r
library(tidyverse)

subscriptions |>
  filter(monthly_spend >= 60) |>
  mutate(call_rate = service_calls / pmax(tenure_months, 1)) |>
  group_by(churned) |>
  summarise(
    customers = n(),
    avg_spend = mean(monthly_spend),
    avg_call_rate = mean(call_rate),
    .groups = "drop"
  )
```

管道符 `|>` 的作用不是让代码显得更复杂，而是把操作顺序写成人可以顺着读下去的流程。数据从左边进入，依次完成筛选、变换、分组和汇总。

### 导入数据时先处理数据类型

CSV、Excel 和数据库中的数据进入 R 后，首先要确认类型是否正确。日期被读成字符、金额被读成文本、类别变量被误当成数字，都会在后续分析中制造隐蔽问题。

```r
orders <- readr::read_csv(
  "data/orders.csv",
  col_types = cols(
    order_id = col_integer(),
    order_date = col_date(),
    customer_id = col_integer(),
    order_value = col_double()
  )
)
```

数据导入不是“打开文件”这么简单。它决定了后续计算使用什么语义，因此应该把列类型、缺失值编码和日期格式看作分析的一部分。

## 第二部分：可视化先回答“数据长什么样”

### 分布比平均数更早出现

一个平均数只能描述中心位置，无法告诉读者分布是否偏斜、是否有多个峰、是否存在长尾或极端值。连续变量开始分析时，直方图、密度图和经验累积分布函数通常比单独打印均值更有信息。

```r
orders |>
  ggplot(aes(order_value)) +
  geom_histogram(bins = 30)
```

直方图的形状会受 bin width 影响。分箱太窄容易把随机波动放大，太宽则可能把多个结构合并掉。密度图也有类似问题，只是控制参数变成 bandwidth。

```r
orders |>
  ggplot(aes(order_value)) +
  geom_density()
```

密度曲线的纵轴不是“某个数值出现的概率”。对于连续变量，概率对应的是某个区间下的面积，整条密度曲线下面积为 1。

### 用 eCDF 看“低于某个值的比例”

经验累积分布函数记作：

\[
F(a)=\frac{\#\{x_i\le a\}}{n}
\]

它直接回答“样本中有多少比例不超过阈值 \(a\)”。在服务时长、配送时间、订单金额等业务变量上，eCDF 很适合回答 SLA 或分位数问题。

```r
orders |>
  ggplot(aes(order_value)) +
  stat_ecdf()
```

例如，当 `F(500)=0.82` 时，可以说约 82% 的订单金额不高于 500。这个解释比“密度在 500 附近是多少”更直接。

### 分位数、箱线图和异常值

中位数是 50% 分位数，四分位距：

\[
IQR=Q_{0.75}-Q_{0.25}
\]

能够描述中间 50% 数据的跨度。箱线图常用 \(1.5\times IQR\) 规则标记远离箱体的观察，但这些点只能叫“需要检查的极端观察”，不能自动判定为错误数据。

```r
orders |>
  ggplot(aes(x = region, y = order_value)) +
  geom_boxplot()
```

某个大额订单可能是录入错误，也可能是真实的大客户交易。删除异常值之前，需要先理解数据生成过程。

### 分组图形要防止聚合掩盖差异

整体数据看起来稳定，并不代表每个客户群、地区或渠道都稳定。分组箱线图、小提琴图和 faceting 可以帮助判断总体结构是否由多个不同子群体混合而成。

```r
subscriptions |>
  ggplot(aes(churned, monthly_spend)) +
  geom_boxplot()
```

如果不同组之间差异明显，后面的回归模型或分类模型就需要考虑这些组别信息。可视化不是报告末尾的装饰，而是模型设定之前的诊断工具。

### 散点图先看关系，再算相关系数

相关系数可以压缩两个变量之间的线性关系，但它无法展示非线性、分组结构和极端点。

```r
subscriptions |>
  ggplot(aes(tenure_months, monthly_spend, colour = churned)) +
  geom_point()
```

同样的相关系数可以对应完全不同的散点结构。看到一个较高的相关系数后，仍然应该看散点图，再决定线性关系是否是合理总结。

## 第三部分：数据整理决定后面的模型是否可信

### tidy data 是分析接口

一张适合分析的数据表通常满足：每个变量一列、每个观察一行、每个观察单位一种表。这个规则看起来简单，但很多业务文件会把月份横向铺开、把多个指标塞进一个字段，或者把表头拆成两三层。

`pivot_longer()` 和 `pivot_wider()` 用来在宽表和长表之间转换。

```r
monthly_sales_long <- monthly_sales |>
  pivot_longer(
    cols = starts_with("2026_"),
    names_to = "month",
    values_to = "sales"
  )
```

长表通常更适合 `ggplot2`、分组统计和模型公式，因为同一种变量集中在同一列中。

### join 前先确认键和粒度

连接表格最危险的问题往往不是语法，而是粒度不一致。客户表一行一个客户，订单表一行一个订单，如果再连接一张“一行一个订单明细”的表，行数可能快速膨胀。

```r
customers |>
  left_join(orders, by = "customer_id")
```

join 前至少要确认三件事：连接键是否唯一、两张表的观察单位是什么、连接后期望得到多少行。否则重复行会悄悄改变均值、总额甚至训练样本权重。

### 缺失值不是一个统一问题

`NA` 只表示“此处缺少值”，并不说明为什么缺。缺失可能来自未记录、未发生、不适用、系统错误或选择性缺失。这些机制对统计推断和预测模型的影响完全不同。

最简单的分析可以先检查：

```r
subscriptions |>
  summarise(across(everything(), ~ sum(is.na(.x))))
```

但在正式模型中，不能把 `na.rm = TRUE` 当成默认解决方案。删除缺失记录会改变样本组成；用均值填补则会压低变异，并可能破坏变量之间的关系。处理方式应该由数据生成过程和预测场景决定。

### 日期、文本和类别变量要显式处理

日期不是字符串，类别也不应该随意编码成连续数字。把字段转成正确类型以后，模型和图表的含义才稳定。

```r
orders <- orders |>
  mutate(
    order_month = lubridate::floor_date(order_date, "month"),
    channel = factor(channel),
    region = factor(region)
  )
```

对于文本字段，正则表达式适合提取具有稳定格式的信息，但不要把临时字符串规则写成无法解释的黑盒。每一步转换最好都能说明为什么需要、输入是什么、输出应该长什么样。

### 建模前先检查信息泄漏

数据泄漏发生在模型训练时使用了真实预测时点无法获得的信息。例如要预测客户下个月是否流失，却把“账户关闭日期”放进特征；或者在划分测试集以前用全体数据计算标准化均值。

泄漏模型的验证分数往往异常漂亮，但上线后会快速失效。建模表中的每一个特征都应该问一句：在真正发出预测的那个时刻，这个字段是否已经可用？

## 第四部分：统计分析把样本规律和不确定性放在一起

### 先区分样本、总体、参数和估计量

统计推断的核心问题是：手里只有样本，却希望对更大的总体作出判断。

总体中真正关心但通常看不到的量称为参数，例如总体平均订单金额 \(\mu\)。样本中计算出的平均值 \(\bar X\) 是参数的估计量。

\[
\bar X=\frac{1}{n}\sum_{i=1}^{n}X_i
\]

换一批随机样本，\(\bar X\) 通常会变。因此一个估计值不能只报告“是多少”，还要说明它有多不稳定。

### 标准误描述估计量的抽样波动

如果观测独立同分布，样本均值的标准误可以近似写成：

\[
SE(\bar X)=\frac{s}{\sqrt n}
\]

这里的 \(s\) 是样本标准差。样本量增加时，标准误按照 \(1/\sqrt n\) 缩小。这也解释了为什么把样本量扩大四倍，标准误大约只能减半，而不是缩小到四分之一。

标准差和标准误经常被混淆：标准差描述个体数据的离散程度，标准误描述一个估计量在重复抽样中的波动程度。

### 中心极限定理连接样本均值和正态近似

在较宽条件下，当样本量足够大时，标准化后的样本均值会接近标准正态分布：

\[
\frac{\bar X-\mu}{\sigma/\sqrt n}\approx N(0,1)
\]

这个结果并不要求原始数据本身一定服从正态分布。它讨论的是样本均值的抽样分布。原始数据高度偏斜或存在重尾时，达到“足够大”的样本量可能需要更多观察，因此不能把中心极限定理当成忽略数据形状的许可证。

### 置信区间表达估计精度

常见的大样本 95% 置信区间写成：

\[
\hat\theta \pm 1.96\times SE(\hat\theta)
\]

对样本均值而言：

\[
\bar X \pm 1.96\frac{s}{\sqrt n}
\]

95% 置信区间的频率学解释是：如果重复执行同样的抽样和构造区间过程，长期来看约 95% 的区间会覆盖真实参数。它不是“真实参数有 95% 概率落在已经算出的这个区间里”的直接概率陈述。

样本很小且总体方差未知时，均值区间通常使用 t 分布而不是固定的 1.96。数据结构更复杂时，标准误和区间也要随抽样设计、模型和相关结构改变。

### 假设检验不是只看 p 值

假设检验通常从一个零假设开始，例如：

\[
H_0:\mu_A-\mu_B=0
\]

检验统计量衡量观察结果距离零假设有多远，p 值衡量在零假设成立以及检验假设满足时，获得同样或更极端结果的概率。

p 值很小不等于效应很大，也不等于模型具有实际价值。样本足够大时，非常小的差异也可能达到统计显著。更完整的报告应该同时看效应大小、标准误、置信区间和业务尺度。

如果一次分析同时检查几十甚至上百个假设，还需要考虑多重比较带来的假阳性膨胀，而不是继续使用每个检验单独的 0.05 阈值。

### Bootstrap 用数据近似抽样分布

当理论标准误难以直接推导时，可以从原样本中有放回地重复抽样，计算每个 bootstrap 样本上的统计量，用这些重复结果近似估计量的抽样分布。

```r
set.seed(2026)

boot_means <- replicate(
  2000,
  mean(sample(monthly_demand, replace = TRUE))
)

sd(boot_means)
quantile(boot_means, c(0.025, 0.975))
```

Bootstrap 很有用，但它不能修复严重偏差的原始样本。如果原始数据没有代表目标总体，重复抽样只会反复复制同一套偏差。时间序列、聚类抽样或强依赖数据也不能机械地把每一行当作独立观察重抽。

### 回归的中心是条件期望

简单线性回归把结果变量的条件均值写成：

\[
E(Y\mid X=x)=\beta_0+\beta_1x
\]

拟合后得到：

\[
\hat Y=\hat\beta_0+\hat\beta_1X
\]

斜率 \(\hat\beta_1\) 表示在模型设定和数据范围内，X 每增加一个单位，Y 的平均水平预计改变多少。

```r
model <- lm(monthly_spend ~ tenure_months, data = subscriptions)
summary(model)
```

回归线描述平均关系，不保证每一个观察值都接近拟合线。残差：

\[
e_i=y_i-\hat y_i
\]

记录了模型没有解释的部分，也是后续诊断的主要对象。

### R² 不是模型质量的总分

\[
R^2=1-\frac{SSE}{SST}
\]

R² 描述样本中结果变量的变异有多少被当前线性模型解释。它不能独立回答因果关系、残差结构、外推风险和样本外预测表现。

一个高 R² 模型可能只是抓住时间趋势，也可能被少数极端点推动；一个低 R² 模型在噪声很大的业务场景中仍然可能提供有用的平均效应估计。

### 多元回归需要“条件解释”

多元线性模型写成：

\[
E(Y\mid X_1,\ldots,X_p)=\beta_0+\beta_1X_1+\cdots+\beta_pX_p
\]

其中某个系数的解释带有“其他变量保持不变”的条件。例如：

```r
model_multi <- lm(
  monthly_spend ~ tenure_months + service_calls + region,
  data = subscriptions
)
```

`service_calls` 的系数描述 tenure 和 region 相同时，服务联系次数与月消费之间的平均关联。这个条件解释与简单相关系数不同。

同时需要注意共线性。如果两个预测变量高度相关，模型对“联合预测”可能仍然不错，但单个系数会变得不稳定，标准误增加，符号甚至可能随样本改变。

### 逻辑回归把线性预测映射到概率

二分类问题中，可以通过 logit 链接建模条件概率：

\[
\log\left(\frac{p(x)}{1-p(x)}\right)
=\beta_0+\beta_1x_1+\cdots+\beta_px_p
\]

其中：

\[
p(x)=P(Y=1\mid X=x)
\]

如果目标是直接拟合“客户流失”的概率，最清楚的做法是先把事件类显式编码成 1：

```r
subscriptions <- subscriptions |>
  mutate(churn_flag = if_else(churned == "Churn", 1, 0))

logit_fit <- glm(
  churn_flag ~ tenure_months + monthly_spend + service_calls,
  data = subscriptions,
  family = binomial()
)
```

这样 `predict(logit_fit, type = "response")` 对应的就是 `churn_flag = 1`，也就是流失概率。这里显式使用 0/1 还有一个好处：不会把因子 level 的顺序误当成事件定义。若直接把二水平 factor 交给 R 的 binomial `glm()`，第一个 level 会被当作 failure，其余 level 被当作 success，因此 level 顺序必须主动核对。

逻辑回归先给出概率，再通过阈值变成类别。阈值并不是模型自动提供的“唯一正确答案”，它应该根据漏报和误报的业务成本选择。

### 关联不能自动升级成因果

回归控制了一些变量之后，仍然不意味着已经排除了所有混杂因素。观察数据中的系数首先应该解释成条件关联。

因果推断需要更强的设计和假设，例如随机试验、自然实验或明确的识别策略。只要研究问题是“改变 X 是否会导致 Y 改变”，就不能仅凭显著系数作结论。

### 高维数据需要降维和正则化

当预测变量很多，甚至 \(p\) 接近或超过样本量 \(n\) 时，普通最小二乘会变得不稳定。高维分析通常需要矩阵表示、降维或正则化。

PCA 从原始变量的线性组合中寻找解释方差最大的正交方向：

\[
Z_1=a_{11}X_1+a_{12}X_2+\cdots+a_{1p}X_p
\]

主成分的作用是把大量相关变量压缩到少数新的坐标轴，但“解释方差最大”并不等于“对目标变量预测最好”。PCA 本身是无监督降维，不使用结果变量 Y。

正则化则直接修改拟合目标。例如 Ridge 回归在最小二乘损失之外加入 L2 惩罚：

\[
\sum_i(y_i-\hat y_i)^2+\lambda\sum_j\beta_j^2
\]

Lasso 使用 L1 惩罚：

\[
\sum_i(y_i-\hat y_i)^2+\lambda\sum_j|\beta_j|
\]

随着 \(\lambda\) 增大，系数被更强地收缩。Ridge 通常保留所有变量但缩小系数；Lasso 可以把部分系数压到 0，因此也具有变量选择效果。惩罚强度不能凭训练误差决定，应该使用交叉验证等样本外方法选择。

正则化前通常还要注意特征尺度。若变量的量纲差异很大，惩罚会对系数产生不公平影响，因此很多实现会先中心化和标准化预测变量。

## 第五部分：预测算法的目标是对新数据有效

### 先定义预测任务和损失函数

机器学习并不是先选算法，再找问题。需要先明确：结果变量是什么、预测发生在什么时间点、预测结果会触发什么决策、哪一种错误代价最高。

连续结果常用均方误差：

\[
MSE=\frac{1}{n}\sum_{i=1}^{n}(y_i-\hat y_i)^2
\]

分类问题则需要混淆矩阵。二分类可以写成：

| | 实际 Positive | 实际 Negative |
|---|---:|---:|
| 预测 Positive | TP | FP |
| 预测 Negative | FN | TN |

常用指标包括：

\[
Accuracy=\frac{TP+TN}{TP+TN+FP+FN}
\]

\[
Sensitivity=Recall=\frac{TP}{TP+FN}
\]

\[
Specificity=\frac{TN}{TN+FP}
\]

\[
Precision=\frac{TP}{TP+FP}
\]

\[
F_1=2\frac{Precision\times Recall}{Precision+Recall}
\]

当正类很少时，Accuracy 可能非常误导。一个“全部预测为负类”的模型也可能得到很高准确率。此时更应该看 sensitivity、precision、F1、ROC 或 precision-recall 曲线，并结合正类 prevalence 解读。

### 训练集和测试集必须承担不同角色

训练数据用于估计模型和选择参数，测试数据用于模拟模型面对真正新数据时的表现。测试集一旦被频繁查看并参与模型调整，就不再是独立测试集。

下面的代码假设 `customer_model_df` 是已经完成字段定义、拥有足够样本量的建模表。对二分类评估，事件类显式放在 factor 的第一水平，后面的 caret 指标就会把 `Churn` 作为关注类别。

```r
library(caret)

customer_model_df <- customer_model_df |>
  mutate(churned = factor(churned, levels = c("Churn", "Stay")))

set.seed(2026)
index <- createDataPartition(
  customer_model_df$churned,
  p = 0.80,
  list = FALSE
)

train_df <- customer_model_df[index, ]
test_df <- customer_model_df[-index, ]
```

对时间序列、客户生命周期或分批采集的数据，随机切分未必合理。如果未来数据发生在过去数据之后，应优先使用时间顺序切分，避免把未来信息泄漏到训练阶段。

### 过拟合来自“模型太贴训练数据”

训练误差通常随着模型复杂度增加而下降，但测试误差不会无限下降。模型过于简单时存在较高 bias；模型过于灵活时则可能把随机噪声当成规律，导致 variance 增大。

机器学习中的很多方法都在处理这组权衡：

- kNN 用邻居数 \(k\) 控制平滑程度；
- 决策树用深度、叶节点大小等控制复杂度；
- 随机森林通过多棵随机树的平均降低单棵树的不稳定性；
- Ridge/Lasso 用惩罚强度控制系数规模；
- PCA 用保留主成分个数控制表示维度。

因此“更复杂”不等于“更强”。一个新算法只有在独立评估中稳定优于简单基线，复杂度才有充分理由。

### 交叉验证用于模型选择，不是装饰

k-fold cross-validation 把训练数据分成 \(k\) 份。每次用其中一份做验证，其余 \(k-1\) 份训练模型，轮流完成后对验证结果求平均。

如果要选择 kNN 的邻居数，可以比较多个候选值。候选 k 不能大于每个重采样训练折中实际可用的样本量，因此网格应根据数据规模设置。

```r
control <- trainControl(method = "cv", number = 5)

grid <- data.frame(k = c(5, 9, 15, 21, 31))

knn_fit <- train(
  churned ~ tenure_months + monthly_spend + service_calls,
  data = train_df,
  method = "knn",
  preProcess = c("center", "scale"),
  tuneGrid = grid,
  trControl = control
)
```

这里最重要的不是 `train()` 的语法，而是每一个候选 k 都必须用“没参与该次拟合的数据”评价。直接选择训练准确率最高的 k，会天然偏向过度灵活的模型。

### 特征预处理必须只从训练数据学习

标准化、缺失值填补、PCA、特征筛选等步骤如果使用了完整数据，就可能提前看到测试集信息，形成 data leakage。

正确流程是：先划分训练/测试，再只用训练集估计均值、标准差、填补规则或 PCA 载荷，然后把相同变换应用到验证集和测试集。

这一点在高维模型里尤其重要。哪怕只是一项看起来很普通的“删除低方差变量”，如果阈值是查看测试集后确定，也已经污染了最终评估。

### 线性回归和逻辑回归也是机器学习基线

机器学习并不排斥经典统计模型。线性回归适合连续结果，逻辑回归适合分类概率。它们的优势是训练快、结构清楚、解释性强。

一个复杂模型如果只能带来很小的样本外改善，却显著增加部署、解释和维护成本，那么线性或逻辑回归往往仍是更好的业务选择。

### kNN 用局部邻域做预测

k-nearest neighbors 不建立一条全局方程。对新观察 \(x_0\)，先找到训练数据中距离最近的 k 个观察，再用邻居的结果做平均或多数投票。

二分类时，可以用邻居中正类比例估计：

\[
\hat p(x_0)=\frac{1}{k}\sum_{i\in N_k(x_0)}y_i
\]

k 小时模型更灵活，容易追随局部噪声；k 大时更平滑，可能把真正的局部结构抹掉。由于距离计算对尺度敏感，使用 kNN 前通常需要标准化预测变量。

### Naive Bayes、LDA 和 QDA 从概率模型出发

另一类分类方法通过各类别下预测变量的分布来计算后验概率。

Naive Bayes 使用条件独立假设简化联合分布，因此计算效率高，即使假设并不完全成立，也可能取得不错预测效果。

LDA 假设不同类别共享相同协方差结构，因此得到线性决策边界；QDA 允许各类别拥有不同协方差矩阵，边界更灵活，但需要估计更多参数。样本量不够时，QDA 更容易产生高方差。

这些方法和逻辑回归的出发点不同：逻辑回归直接建模给定 X 的类别概率，而 LDA/QDA 先描述各类别中的 X 分布，再通过 Bayes 规则得到后验概率。

### CART 用递归切分形成规则

分类与回归树通过不断选择变量和切分点，把特征空间分成多个区域。每个叶节点对应一个预测值或类别概率。

树模型很容易解释，例如：

```text
service_calls >= 4
├── tenure_months < 10  → 高流失风险
└── tenure_months >= 10 → 中等风险
```

但单棵树对样本扰动非常敏感。一小部分记录变化就可能产生不同的第一层切分，因此稳定性通常不如集成模型。剪枝或控制叶节点大小可以限制模型复杂度。

### 随机森林用“许多不一样的树”降低方差

随机森林的核心是同时引入两种随机性：bootstrap 样本和随机特征子集。先构建很多棵彼此不同的树，再对它们的预测取平均或多数投票。

连续结果可以写成：

\[
\hat y=\frac{1}{B}\sum_{b=1}^{B}T_b(x)
\]

分类任务则可以对树的类别预测投票，或者平均各树输出的类别概率。

相比单棵树，随机森林通常更稳定，但解释性也更弱。变量重要性可以帮助理解哪些特征经常参与有效切分，不过“重要”不等于“具有因果作用”。

### 用 caret 统一训练接口

不同 R 包的模型函数参数差异很大。`caret::train()` 提供统一接口，让模型比较更集中在数据切分、预处理、重采样和超参数，而不是被各个包的语法差异打断。

在下面的二分类设置中，`Churn` 已经被放在 factor 的第一水平，因此 `twoClassSummary` 的 Sensitivity、Specificity 和 ROC 都以该事件类为关注对象。

```r
control <- trainControl(
  method = "cv",
  number = 5,
  classProbs = TRUE,
  summaryFunction = twoClassSummary
)

logit_cv <- train(
  churned ~ tenure_months + monthly_spend + service_calls,
  data = train_df,
  method = "glm",
  family = binomial(),
  metric = "ROC",
  trControl = control
)
```

对实际项目而言，统一接口最大的价值是让模型比较使用同一套 resampling 方案。否则模型 A 用 10-fold CV，模型 B 用训练误差，模型 C 用一次随机切分，最终表格中的性能数字并不可比。

### 模型诊断不能只看一个排行榜

模型评估至少要回答四类问题：

1. **总体表现**：MSE、AUC、F1 或其他核心指标是多少；
2. **误差结构**：哪些客户群、区域、金额区间或类别最容易出错；
3. **稳定性**：换折、换样本或换时间窗口以后结果是否剧烈变化；
4. **可用性**：输出是否能在真实决策流程中被解释和执行。

例如客户流失模型 AUC 较高，但如果它几乎只识别高消费客户，而对低消费但高数量的客户群表现很差，整体指标可能掩盖重要业务问题。

### ROC 和 PR 曲线回答不同问题

ROC 曲线用不同阈值下的 sensitivity 与 false positive rate 形成曲线，AUC 衡量模型对随机正负样本排序的能力。

Precision-recall 曲线则直接关注 positive predictions 的质量和正类召回情况。当正类非常稀少时，PR 曲线通常比 ROC 更能反映业务真正关心的性能。

因此不平衡分类不能只报 Accuracy，也不应该机械地认为 AUC 越高就一定越好。阈值后的实际成本仍然需要单独评估。

### 概率校准和排序能力是两回事

AUC 主要考察排序能力。一个模型可以很好地把高风险客户排在前面，但输出的 0.8 未必真的意味着相似客户中约 80% 会发生事件。

如果概率会直接进入定价、资源分配或期望收益计算，还应该检查 calibration。常见做法是按预测概率分组比较预测概率与实际发生率，或者查看 calibration curve 和 Brier score。

### Ensemble 只有在模型“犯不同错误”时才有价值

集成模型把多个预测器组合起来。简单方法可以对类别多数投票，也可以平均各模型的预测概率。

如果两个模型几乎总是做出相同判断，组合它们不会带来多少新信息。集成真正有价值的条件通常是：单个模型都有一定能力，同时它们的误差并不完全相同。

参考资料以不同监督学习方法说明这种思想。实际业务里也可以把逻辑回归、树模型和其他方法放在同一验证框架中比较，再决定组合是否真的改善样本外表现。

### 无监督学习没有 Y，也必须定义“好”的标准

聚类与监督学习不同，没有已知标签作为训练目标。算法只根据特征空间中的相似性组织观察。

k-means 通过最小化簇内平方距离寻找 K 个簇：

\[
\sum_{k=1}^{K}\sum_{i\in C_k}\|x_i-\mu_k\|^2
\]

它对尺度和初始中心敏感，因此数值变量通常需要标准化，并使用多个随机初始值。

```r
x <- scale(customer_features)
set.seed(2026)
km <- kmeans(x, centers = 4, nstart = 30)
```

K 本身也不是算法自动决定的真理。可以参考 within-cluster sum of squares、silhouette 等内部指标，但最终仍要看分组是否稳定、是否能够解释、是否对应实际可执行的客户或运营策略。

聚类结果不能因为算法成功运行就直接贴上“高价值客户”“流失客户”之类业务标签。先检查各簇在真实变量上的差异，再判断这种分组是否稳定、可解释和可行动。

### 一条可靠的预测建模顺序

面对新的预测任务，可以按下面的顺序推进：

1. 明确预测对象、预测时点和结果变量；
2. 检查每一行代表什么，排除明显数据泄漏；
3. 查看分布、缺失、异常值和变量关系；
4. 先建立简单基线模型；
5. 设计训练、验证和最终测试方案；
6. 把预处理放进训练流程内部；
7. 用交叉验证选择超参数；
8. 比较多个结构不同的模型；
9. 根据业务成本选择分类阈值；
10. 在从未参与调参的测试集上只做一次最终评估；
11. 逐群体检查错误，而不是只看总指标；
12. 保存数据版本、代码、模型参数和评估结果，确保之后可以重跑。

这条顺序比“先把所有算法跑一遍再挑准确率最高的”可靠得多。预测建模真正要优化的是新数据上的决策质量，而不是训练集上的漂亮数字。

## 从统计分析到机器学习，边界没有想象中那么硬

统计分析通常更强调参数、估计、不确定性和解释；机器学习更强调预测误差、重采样、模型选择和泛化。但两者共享大量核心思想：条件期望、损失函数、偏差与方差、抽样波动、正则化、模型诊断。

线性回归既可以用于解释平均关系，也可以作为预测算法；Bootstrap 既可以估计标准误，也可以成为集成学习中的抽样机制；交叉验证既可以调机器学习超参数，也可以比较回归模型的样本外性能。

真正重要的不是给方法贴上“统计”还是“机器学习”的标签，而是明确当前问题需要哪一种证据。需要解释变量作用时，系数和区间很重要；需要预测未来记录时，样本外评估和数据泄漏控制更重要；需要把分析交给别人复查时，可重复运行的项目结构又变成核心要求。

生产环境中的可靠分析，往往正是这些能力共同工作的结果。
