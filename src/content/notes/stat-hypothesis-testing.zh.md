## 假设检验回答的不是“谁对谁错”

假设检验常被简化成一句“p < 0.05 就显著”，但真正的问题是：**如果某个基准假设成立，当前数据有多不寻常。**

例如一个客服流程原本平均等待时间是 12 分钟，新流程上线后抽取一批记录，希望判断平均等待时间是否发生变化。

可以写成：

\[
H_0:\mu=12
\]

\[
H_1:\mu\ne12
\]

其中 \(H_0\) 是 null hypothesis，\(H_1\) 是 alternative hypothesis。

检验并不是直接计算“\(H_0\) 为真的概率”。它先假设 \(H_0\) 成立，再看当前样本统计量离这个假设有多远。

## 先定义参数，再写原假设

一个好的检验问题应该先明确参数。

如果研究平均等待时间，参数是总体均值 \(\mu\)；如果研究准时率，参数是总体比例 \(p\)；如果比较两组，参数可能是 \(\mu_A-\mu_B\) 或 \(p_A-p_B\)。

不要从“该用哪个 test”开始，而应从“真正想判断的总体量是什么”开始。

例如比较两个配送方案的平均时间：

\[
H_0:\mu_A-\mu_B=0
\]

如果业务只关心 A 是否更快，也可以设为单侧问题：

\[
H_1:\mu_A-\mu_B<0
\]

但单侧方向应该在看结果之前由问题定义，不能看到数据方向以后再临时修改。

## 检验统计量把差异除以随机波动

很多检验统计量都具有类似结构：

\[
\text{test statistic}=\frac{\text{observed estimate}-\text{null value}}{\text{standard error}}
\]

单样本均值 t statistic：

\[
t=\frac{\bar X-\mu_0}{s/\sqrt n}
\]

如果样本均值只比 null value 偏一点，但标准误非常小，统计量仍可能很大；如果均值差很多但样本很少、波动很大，统计证据反而可能较弱。

```r
wait <- c(10.8, 11.6, 12.3, 10.9, 11.2, 12.0, 11.4, 10.7, 11.8, 11.1)
t.test(wait, mu = 12)
```

R 输出中的 estimate、confidence interval、t statistic 和 p-value 应该一起读，而不是只截取最后一个数字。

## p 值的条件非常重要

p-value 是：**在原假设和检验模型成立的条件下，观察到当前结果或更极端结果的概率。**

它不是：

- 原假设为真的概率；
- 结果由随机造成的概率；
- 研究结论为假的概率；
- 效果大小；
- 模型预测准确率。

假设某检验得到 `p = 0.03`，合理表述是：如果 \(H_0\) 成立并且模型假设合适，那么得到当前或更极端统计量的概率约为 3%。

不应该写成“原假设只有 3% 的概率是真的”。

## 0.05 不是自然界的分界线

显著性水平 \(\alpha\) 是人为设定的决策阈值。常见的 0.05 只是惯例，不是数据自动产生的真理。

`p = 0.049` 和 `p = 0.051` 所代表的证据强度几乎连续，却经常因为一个固定阈值被写成完全不同的结论。

更好的做法是同时报告：

- 参数估计；
- confidence interval；
- p-value（确有需要时）；
- 样本量；
- 实际效果大小；
- 业务含义。

如果一项结果只有“显著/不显著”两个标签，通常丢掉了太多信息。

## 置信区间和假设检验是同一套信息的两种表达

对于常见双侧检验，如果 95% confidence interval 不包含 null value，通常对应双侧 p-value < 0.05。

例如均值差的 95% CI 为：

```text
[-4.8, -1.1] minutes
```

零不在区间内，对应“没有平均差异”的 null hypothesis 会被 5% 水平下拒绝。

如果区间为：

```text
[-3.2, 0.7] minutes
```

零仍然与数据相容。

区间通常比单独 p 值更有解释力，因为它还告诉读者效果可能有多大。

## 第一类和第二类错误是两种不同风险

统计决策可能犯两类错误。

| 真实状态 | 不拒绝 H0 | 拒绝 H0 |
|---|---|---|
| H0 真实 | 正确 | 第一类错误 |
| H0 不真实 | 第二类错误 | 正确 |

**第一类错误**：实际上没有效果，却错误地宣布存在效果。其长期错误率由 \(\alpha\) 控制。

**第二类错误**：实际上存在效果，却因为证据不足没有检测到。常记为 \(\beta\)。

Power 定义为：

\[
Power=1-\beta
\]

也就是当某个真实效果存在时，检验能够检测到它的概率。

## 检验功效为什么取决于样本量和效果大小

Power 不是一个固定属性。它受以下因素影响：

- 样本量；
- 真实效果大小；
- 数据波动；
- 显著性水平；
- 单侧或双侧设计；
- 检验方法。

同样一个很小的真实差异，在 30 个样本中可能很难发现，在 30,000 个样本中却容易得到很小的 p 值。

R 中可以做基础功效计算：

```r
power.t.test(
  n = 50,
  delta = 3,
  sd = 10,
  sig.level = 0.05,
  type = "two.sample"
)
```

这里的 `delta` 应该来自业务上值得检测的差异，而不是事后用观察到的效果反推所谓“observed power”。

## 大样本会让很小的差异也显著

假设一个新界面把平均处理时间从 20.00 秒降到 19.85 秒。样本有数百万条时，这 0.15 秒差异可能得到极小 p 值。

统计上强证据不等于业务上重要。

因此需要单独问：

- 差异有多大；
- 区间有多宽；
- 单位是什么；
- 换算成客户体验、成本或容量以后有多大影响；
- 实施成本是否值得。

Effect size 和 uncertainty 比“星号数量”更接近实际决策。

## 两样本均值常用 Welch t-test

比较两个独立群体的均值时，R 的 `t.test()` 默认使用 Welch t-test，不要求两组总体方差完全相等。

```r
delivery <- data.frame(
  method = rep(c("Current", "New"), each = 15),
  hours = c(
    31, 29, 35, 34, 28, 33, 36, 30, 32, 37, 29, 34, 31, 35, 30,
    27, 26, 29, 28, 25, 30, 27, 29, 26, 28, 24, 30, 27, 26, 29
  )
)

t.test(hours ~ method, data = delivery)
```

除了 p 值，更值得关注的是两组均值、均值差的 confidence interval，以及数据分布是否存在异常结构。

```r
boxplot(hours ~ method, data = delivery)
```

先看图再读检验结果，通常比先跑 test 更稳妥。

## 配对数据不能按独立样本处理

如果同一批客户在改版前后各测一次，两个观察不是独立的。

```r
before <- c(18, 22, 20, 25, 19, 21, 24, 23)
after  <- c(16, 20, 19, 21, 18, 20, 22, 21)

t.test(before, after, paired = TRUE)
```

配对设计真正分析的是每个对象内部差值：

\[
D_i=X_{i,before}-X_{i,after}
\]

如果错误地使用独立样本检验，会丢掉配对信息，并且标准误计算不再对应实际设计。

## 比例检验也从同一逻辑出发

假设原准时率是 90%，现在抽取 300 张订单，其中 282 张准时：

```r
prop.test(
  x = 282,
  n = 300,
  p = 0.90,
  correct = FALSE
)
```

这里检验的是：

\[
H_0:p=0.90
\]

比例数据属于二元/计数结构，不能因为“也有平均数”就完全照搬连续变量的方法。样本小或事件稀少时，需要考虑精确二项方法：

```r
binom.test(282, 300, p = 0.90)
```

## 多重检验会制造假阳性

如果每个检验都使用 \(\alpha=0.05\)，一次只做一个检验时第一类错误受到控制；但同时做很多检验，至少出现一个假阳性的概率会明显上升。

假设做 20 个彼此独立、真实 null 的检验：

\[
P(\text{至少一个假阳性})=1-(1-0.05)^{20}\approx0.64
\]

因此“把所有字段都和结果变量检验一遍，再挑 p < 0.05 的变量”很容易制造偶然发现。

常见调整包括 Bonferroni 与 false discovery rate：

```r
p_values <- c(0.003, 0.018, 0.041, 0.12, 0.40)
p.adjust(p_values, method = "bonferroni")
p.adjust(p_values, method = "BH")
```

选择方法取决于错误成本和研究目标，不能把调整当作固定仪式。

## 假设前提不成立时，p 值也会失去原本含义

每个检验都依赖数据和模型条件，例如独立性、抽样机制、分布近似或方差结构。

特别常见的问题包括：

- 同一客户出现多条记录，却按独立样本处理；
- 时间序列有自相关，却使用独立误差公式；
- 严重选择偏差，却把样本当随机样本解释；
- 先看结果再决定检验方向；
- 重复尝试许多筛选规则，只报告最小 p 值。

这些问题不是再换一个 test 名称就能自动解决。

## “没有显著差异”不等于“两个方案一样”

如果 `p = 0.30`，只能说明数据没有提供足够证据拒绝当前 null hypothesis。

原因可能是：

- 真实效果确实很小；
- 样本量太小；
- 数据波动太大；
- 测量质量差；
- 研究设计不够敏感。

如果真正问题是“两个方案是否足够接近”，应该考虑 equivalence / non-inferiority 一类明确围绕可接受差异范围设计的问题，而不是把普通不显著结果直接翻译成“相同”。

## 一条更可靠的检验流程

面对统计检验，可以按下面顺序检查：

1. 明确总体、参数和业务问题；
2. 写出 null / alternative hypothesis；
3. 确认单侧还是双侧，并在看结果前固定；
4. 检查抽样、独立性、配对和数据类型；
5. 先看图和描述统计；
6. 选择与设计相符的统计量；
7. 同时报告 effect estimate、confidence interval 和 p-value；
8. 检查样本量与 power；
9. 多重检验时控制整体错误；
10. 最后再讨论实际业务意义。

这个顺序能把假设检验从“阈值判断器”变回一套统计证据工具。
