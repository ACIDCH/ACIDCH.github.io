## 先把三个容易混淆的概念分开

回归图里总会有一些点特别显眼，但“显眼”并不等于“应该删除”。判断之前，至少要把 outlier、high leverage 和 influential observation 分开。

**Outlier** 通常指 Y 方向上离模型比较远的观察，也就是残差很大。**High leverage point** 指 X 的组合位于样本的边缘位置。**Influential observation** 则强调结果：如果拿掉这条记录，模型系数、拟合值或结论会明显改变。

三者可能重叠，也可能完全不是同一批记录。

一个点可以残差很大，但 X 很普通；也可以 X 很极端，却恰好落在回归趋势上。真正容易把回归线拉动的，通常是 leverage 较高、同时 residual 也不小的观察。

## 大残差说明模型在 Y 方向上没解释好

残差是：

\[
e_i=y_i-\hat y_i
\]

如果某条记录的实际值和预测值差得很远，它就是一个值得检查的 residual outlier。

不过原始残差会受到整体误差尺度影响，因此更常比较 standardized residual 或 studentized residual。它们把残差放到相对统一的尺度上，更容易发现哪些记录明显偏离大多数数据。

R 中可以查看：

```r
rstandard(model)
rstudent(model)
```

大残差只说明“这一条记录的 Y 不太符合当前模型”，并不能单独说明它会严重改变系数。

## High leverage 来自 X 空间，而不是 Y

Leverage 关注的是解释变量位置。

在线性回归中，hat matrix 为：

\[
H=X(X^TX)^{-1}X^T
\]

对角线上的 \(h_{ii}\) 就是第 i 条记录的 leverage。

如果某条记录的 X 组合远离大部分样本，它的 leverage 往往更高。直观地说，这种记录站在数据云的边缘，回归线为了兼顾它可能需要转动更多。

简单回归里很好理解：大多数 X 都在 10 到 20 之间，突然有一条 X=60，这条记录通常会有很高的 leverage。

R 可以直接查看：

```r
hatvalues(model)
```

高 leverage 并不等于异常数据。它可能只是一个真实、少见、但很有信息量的业务案例。

## 影响点看的是“拿掉以后会怎样”

Influence 关注的是模型对某条记录有多敏感。

假设删除一条记录后：

- 斜率明显改变；
- 某个系数符号翻转；
- 预测结果大幅移动；
- 原本显著的变量变得不显著；
- 业务结论发生变化。

那么这条记录就具有较强影响力。

这类判断比“点离直线远不远”更接近实际建模风险，因为最终关心的是模型结论是否依赖少数记录。

## Cook’s distance 把残差和 leverage 放在一起

Cook’s distance 是最常用的影响诊断之一。它衡量删除某条记录以后，整体拟合会改变多少。

常见形式可以写成：

\[
D_i=\frac{e_i^2}{p\cdot MSE}\frac{h_{ii}}{(1-h_{ii})^2}
\]

公式里同时出现 residual 和 leverage，所以一个点要真正产生较大 Cook’s distance，通常既要在 Y 上有偏离，又要在 X 空间里有一定位置优势。

R 中：

```r
cooks.distance(model)
```

经常有人用 `4/n` 或 1 作为经验参考线。这些值适合帮助筛查，不适合作为自动删除标准。一个点超过阈值，意思是“值得看”，不是“必须删”。

## DFBETA 更适合追踪某一个系数

Cook’s distance 看的是整体模型变化，DFBETA 则更细：它关心删除第 i 条记录后，某一个回归系数会改变多少。

如果业务最关心的是某个关键变量的斜率，例如价格弹性、配送距离效应或风险系数，那么 DFBETA 往往比一个总影响指标更有针对性。

R 中可以得到每条记录对每个系数的影响：

```r
dfbeta(model)
```

或者标准化后的：

```r
dfbetas(model)
```

这能帮助区分两种情况：某条记录整体影响很大，和某条记录主要改变某一个关键系数。

## 极端点先查数据，不要先删数据

发现异常记录以后，最有价值的第一步是回到原始数据。

可以检查：

- 数值是不是录错了一位；
- 单位有没有混用；
- 日期、币种或分类是否一致；
- 这条记录是不是重复；
- 它是否来自不同业务机制；
- 是否存在遗漏变量能够解释它。

如果确认是录入错误，修正或删除是数据清洗。如果记录真实存在，就应该把它当作建模信息，而不是因为“看起来不好看”就拿掉。

真实极端案例有时恰恰代表风险最高、最值得研究的业务场景。

## 最可靠的做法是做敏感性分析

面对一个高影响点，最清楚的办法通常不是争论它“算不算异常”，而是直接比较模型。

```r
model_full <- lm(y ~ x1 + x2, data = df)
model_drop <- lm(y ~ x1 + x2, data = df[-suspect_row, ])

coef(model_full)
coef(model_drop)
```

然后比较：

- 关键系数改变多少；
- 置信区间是否明显变化；
- R² 和预测误差是否改变；
- 业务结论是否翻转。

如果结论几乎不变，就说明模型对这条记录相对稳健。如果结论高度依赖它，就需要在报告里明确说明，而不是悄悄删掉以后只展示“更漂亮”的结果。

## 高影响点也可能提示模型漏掉了结构

有时某个点看起来很异常，并不是数据有问题，而是模型太简单。

例如一个客户属于完全不同的渠道，一台设备采用了不同技术，一组订单处在特殊促销期。如果这些结构没有进入模型，对应记录就可能表现为大残差或高影响。

这时真正需要做的可能是加入合理的类别变量、交互项，或者重新定义分析范围，而不是删除记录。

所以影响诊断不只是“清理异常值”的工具，也能帮助发现模型遗漏了什么。

## 预测和解释对影响点的敏感程度不同

如果目标是解释某个系数，高影响点尤其重要，因为它可能改变系数大小甚至方向。

如果目标是预测，则要进一步看这条记录是否代表未来也会出现的情况。一个真实但少见的边缘场景，如果未来业务仍然会出现，模型就不能通过删掉它来逃避问题。

相反，如果它属于已经不会再发生的旧流程，建模范围可能需要重新定义。

是否保留一条记录，最终还是要和数据生成过程以及未来使用场景联系起来。

## 常见的错误处理方式

### 看到大残差就直接删除

大残差不等于高影响，更不等于数据错误。

### 用一个阈值自动批量删点

Cook’s distance、leverage 阈值都是筛查工具，不是删除规则。

### 只比较 R²

删除极端点以后 R² 往往会变好，但这并不能证明删除合理。更应该看关键系数和结论是否变化。

### 不记录删点前后的结果

如果模型对某条记录敏感，这本身就是重要结果，应该被保留下来。

## 一套更稳妥的检查顺序

1. 用残差找 Y 方向上的异常；
2. 用 leverage 找 X 空间边缘的观察；
3. 用 Cook’s distance 看整体影响；
4. 用 DFBETA 看关键系数受谁影响；
5. 回到原始数据确认记录是否真实；
6. 比较保留和移除后的模型；
7. 根据业务范围决定是否需要修正模型，而不是只修正数据。

异常点分析真正要回答的不是“怎样把难看的点删掉”，而是**模型的结论有多依赖少数记录，以及这种依赖在业务上是否合理**。
