## 直线拟合不够时怎么办？

线性回归的名字很容易让人误会。线性模型要求的是参数以线性方式进入模型，并不意味着解释变量只能出现一次项。

例如：

\[
Y=\beta_0+\beta_1X+\beta_2X^2+\varepsilon
\]

这条关系在 X 上是弯的，但对 \(\beta_0,\beta_1,\beta_2\) 仍然是线性的，所以可以继续用 OLS 估计。

实际数据里出现弯曲关系很正常。促销投入可能一开始带来明显增长，之后逐渐饱和；机器负荷在低水平时影响不大，接近上限后故障风险却快速上升。直线适合作为起点，但不一定适合做到最后。

## 什么时候应该怀疑直线不够用

最直接的信号通常来自残差图。

如果简单线性模型拟合以后，残差从左到右出现清楚的 U 形、倒 U 形或持续弯曲，说明模型在某些区间一直高估，在另一些区间一直低估。这样的误差不是随机噪声，而是函数形式没有抓住数据结构。

这时先回到业务过程检查：

- 有没有饱和或边际递减；
- 是否存在阈值或拐点；
- X 的影响会不会在不同区间方向不同；
- 曲率是不是由少数极端点造成的。

先弄清楚为什么会弯，再决定加什么项，比看到曲线就直接堆高阶多项式更可靠。

## 二次项是最常见的非线性扩展

最简单的做法之一，是加入 \(X^2\)：

\[
Y=\beta_0+\beta_1X+\beta_2X^2+\varepsilon
\]

这时 \(\beta_1\) 不能再单独解释成“X 每增加 1，Y 固定变化多少”，因为 X 的边际影响已经会随着 X 改变。

对 X 求导：

\[
\frac{dE(Y\mid X)}{dX}=\beta_1+2\beta_2X
\]

也就是说，同样增加 1 个单位的 X，在不同位置上对 Y 的影响可以不同。

如果 \(\beta_2<0\)，曲线向下弯，可能对应边际收益递减；如果 \(\beta_2>0\)，曲线向上弯，可能表示影响随着 X 增大而加速。

## 转折点比单个系数更容易解释

二次模型的转折点是：

\[
X^*=-\frac{\beta_1}{2\beta_2}
\]

当业务问题关心“什么时候开始下降”“在哪个投入水平附近收益最高”时，这个位置往往比单独解释 \(\beta_1\) 和 \(\beta_2\) 更直观。

不过转折点也有边界。若算出的 \(X^*\) 根本不在样本范围内，就不能因为公式给出了一个数字而强行解释。模型在观测区间内有证据，超出区间以后只是外推。

## 多项式阶数越高，不代表模型越好

加入三次、四次甚至更高阶项，训练数据上的拟合通常会继续变好。但曲线也会更容易跟着局部噪声摆动。

高阶多项式常见的问题包括：

- 边界附近出现不自然的剧烈变化；
- 系数很难单独解释；
- 不同幂次的 X 高度相关；
- 训练误差下降，但新数据表现变差。

所以多项式回归的目标不是“把曲线贴得越紧越好”，而是用足够简单的形式表达真实结构。诊断图、样本外验证和业务含义应该一起看。

在 R 里可以直接写：

```r
model_quad <- lm(y ~ poly(x, 2, raw = TRUE), data = df)
```

`raw = TRUE` 表示显式使用 \(x\) 和 \(x^2\)，更适合直接解释原始多项式系数。

## 类别变量进入回归后，会变成组间差异

解释变量不一定都是连续数值。地区、渠道、客户类型、设备类别等变量也可以进入回归。

假设 `channel` 有两个水平：Store 和 Online。选择 Store 作为基准组后，可以写成：

\[
Y=\beta_0+\beta_1X+\beta_2D_{Online}+\varepsilon
\]

其中：

```text
D_Online = 0  → Store
D_Online = 1  → Online
```

这时 \(\beta_2\) 表示在 X 相同的情况下，Online 组与 Store 组的平均水平相差多少。

R 通常会自动处理 factor 的哑变量编码：

```r
df$channel <- factor(df$channel)
model <- lm(y ~ x + channel, data = df)
```

真正要注意的是基准组是谁，因为所有类别系数都相对于它解释。

## 交互项表示一个变量的影响会随另一个变量变化

如果不同渠道不仅平均水平不同，X 的斜率也不同，就需要交互项。

模型可以写成：

\[
Y=\beta_0+\beta_1X+\beta_2D+\beta_3(XD)+\varepsilon
\]

当 D=0 时：

\[
E(Y)=\beta_0+\beta_1X
\]

当 D=1 时：

\[
E(Y)=(\beta_0+\beta_2)+(\beta_1+\beta_3)X
\]

所以 \(\beta_3\) 不是一个孤立的“额外效果”，而是在说两组斜率相差多少。

R 里最常见的写法是：

```r
model_interaction <- lm(y ~ x * channel, data = df)
```

`x * channel` 会同时包含 `x`、`channel` 和 `x:channel`。

## 有交互项以后，主效应的解释会改变

这是交互模型里最容易误读的地方。

当模型中存在 `x:channel` 时，`x` 的系数不再代表“所有渠道下 X 的共同影响”，而是 **基准渠道** 下的 X 斜率。`channel` 的主效应也只对应 X=0 时的组间差异。

如果 X=0 在业务上没有意义，可以考虑中心化：

```r
df$x_centered <- df$x - mean(df$x)
model <- lm(y ~ x_centered * channel, data = df)
```

这样类别主效应就对应“X 处在平均水平时”的组间差异，通常更容易解释。

中心化不会改变模型拟合出来的预测值，只是让系数的参考点更合理。

## 不要为了提高拟合度不断加项

一个模型可以很轻松地加入平方项、三次项、十几个类别变量和大量交互项。难点不是把这些项写进去，而是判断它们是否真的有必要。

比较模型时，可以同时看：

- 残差结构是否明显改善；
- 新增项有没有业务解释；
- 样本外误差有没有下降；
- 参数不确定性有没有变得过大；
- 模型是否仍然能被清楚沟通。

如果复杂模型只让训练 R² 多了一点，却让结果几乎无法解释，它未必比简单模型更有价值。

## 外推时要格外小心

多项式和交互模型在样本范围内可能非常合理，出了样本范围却可能迅速变得荒唐。

尤其是高阶多项式，边界之外的曲线由最高次项主导，增长或下降速度可能远超真实业务过程。因此，预测图最好明确画出训练数据覆盖的 X 区间，不要把数学曲线无限延伸当成可靠预测。

类别交互也有类似边界。如果某个类别只在很窄的 X 区间出现，那么两组斜率在其他区间的比较缺少实际数据支持。

## 实际建模时可以这样检查

1. 先画原始数据和残差图，确认问题真的存在；
2. 用业务过程判断可能是曲率、组间差异还是斜率差异；
3. 从最简单的扩展开始，例如二次项或一个合理交互；
4. 重新看残差和预测表现；
5. 检查系数是否还能给出清楚解释；
6. 避免把样本范围之外的曲线当成事实。

非线性项和交互项的作用，是补上直线模型没有表达出来的结构。能用简单模型解释清楚时不必加复杂度；确实有弯曲或组间差异时，再加入能够被数据和业务共同解释的项。
