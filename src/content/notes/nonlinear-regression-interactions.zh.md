## 线性模型不等于只能画直线

“线性回归”中的线性，核心是模型对参数 \(\beta\) 线性，而不是所有解释变量都必须以一次项进入模型。只要参数仍以线性组合出现，就可以加入平方项、立方项、类别变量哑变量和交互项。

例如：

\[
Y=\beta_0+\beta_1X+\beta_2X^2+\varepsilon
\]

这在 X 上是一条曲线，但对 \(\beta_0,\beta_1,\beta_2\) 仍然是线性模型，可以继续用 OLS 估计。

真正需要回答的问题不是“能不能加二次项”，而是**业务过程是否存在合理曲率，以及增加的项能否改善模型而不过度追逐样本噪声**。

## 多项式回归何时有意义

常见的曲率场景包括：

- 广告投入初期回报明显，后期边际收益递减；
- 员工负荷在低到中等水平影响较小，但接近容量极限后等待时间急剧上升；
- 温度对能源消耗存在 U 型关系；
- 价格过低和过高都可能降低某类转化率。

二次模型写作：

\[
Y=\beta_0+\beta_1X+\beta_2X^2+\varepsilon
\]

此时 \(\beta_1\) 不能再被解释为“X 每增加 1，Y 固定变化 \(\beta_1\)”。边际变化取决于 X：

\[
\frac{dE(Y\mid X)}{dX}=\beta_1+2\beta_2X
\]

因此，多项式模型更适合通过预测曲线、边际效应或若干有业务意义的 X 水平来解释。

## 次数越高并不越好

加入更多次数总能让训练样本的 SSE 不增，通常还会下降，但这不等于样本外表现改善。高次数模型可能在训练区间内拟合得很紧，却在边界附近剧烈弯折，外推尤其不稳定。

多项式次数的选择应综合：

1. 散点图和残差是否显示持续曲率；
2. 新增项是否有明确函数形式解释；
3. nested model 比较是否显示有意义改善；
4. validation/CV 是否支持更高复杂度；
5. 边界行为是否合理；
6. 模型是否仍可稳定沟通。

R 中可以显式写幂次：

```r
model_quad <- lm(y ~ x + I(x^2), data = dat)
model_cubic <- lm(y ~ x + I(x^2) + I(x^3), data = dat)
```

也可以使用 `poly()`。如果目的是直接解释原始幂次系数，需要注意 `poly()` 默认使用正交多项式基，而不是简单的原始 \(x,x^2,x^3\) 系数。

## 转折点与边际效应比单个系数更有解释力

当二次项存在时，业务上经常更关心“边际效果什么时候由正转负”或“哪个区间增长最快”，而不是孤立地阅读 \(\beta_1\) 与 \(\beta_2\)。二次模型的转折点可以由一阶导数等于 0 得到：

\[
x^*=-\frac{\beta_1}{2\beta_2}
\]

但转折点只有落在样本实际覆盖范围内才值得解释。如果历史数据只覆盖 10–60，而计算出的转折点是 140，那么它只是模型外推产生的数学结果，不能被包装成业务阈值。

更稳健的沟通方式是选取几个有业务意义的水平，例如低负荷、中等负荷和高负荷，分别报告预测均值与边际变化。这样既保留非线性信息，也避免把高阶系数表变成难以阅读的数字堆叠。

## 类别变量本质上是在比较基准组

当解释变量是地区、客户层级、渠道或产品类型时，回归需要把类别映射为指示变量。

假设 `channel` 有 Portal 和 Assisted 两类，并把 Portal 作为 reference：

\[
Y=\beta_0+\beta_1I(Assisted)+\varepsilon
\]

此时：

- \(\beta_0\)：Portal 组的平均结果；
- \(\beta_1\)：Assisted 与 Portal 的平均差异。

如果有三类，就需要两个虚拟变量而不是三个，否则会与截距产生完全共线关系。

类别变量的 reference level 会改变系数表的表面形式，但不会改变模型对各组均值的拟合结果。解释前必须先确认 reference，而不是看到某个类别系数就直接下结论。

## 数值变量和类别变量可以放在同一个模型

考虑：

\[
DeliveryHours=\beta_0+\beta_1Distance+\beta_2Priority+\varepsilon
\]

如果 `Priority=1` 表示高优先级，则：

- 普通订单：\(\beta_0+\beta_1Distance\)
- 高优先级：\((\beta_0+\beta_2)+\beta_1Distance\)

两组拥有不同截距，但共享同一条斜率。这个模型隐含一个很强的假设：高优先级只造成固定水平位移，不改变距离对时长的影响。

## 交互项表达“一个变量的效应取决于另一个变量”

加入交互：

\[
Y=\beta_0+\beta_1X+\beta_2G+\beta_3XG+\varepsilon
\]

若 \(G=0\)：

\[
E(Y\mid X,G=0)=\beta_0+\beta_1X
\]

若 \(G=1\)：

\[
E(Y\mid X,G=1)=(\beta_0+\beta_2)+(\beta_1+\beta_3)X
\]

所以 \(\beta_3\) 表示两组斜率之间的差。它不是一个孤立的“额外影响”，而是条件效应。

业务中常见交互包括：

- 距离对配送时长的影响是否因运输模式而不同；
- 价格折扣的影响是否因客户层级而不同；
- 工作负荷对等待时间的影响是否因班次而不同；
- 培训时长与员工经验是否共同改变绩效。

## 有交互时不要单独解释主效应

如果模型包含 \(XG\)，\(\beta_1\) 的含义变成“当 G=0 时 X 的效应”，\(\beta_2\) 变成“当 X=0 时组别差异”。如果 X=0 没有业务意义，这个主效应可能难以解释。

一个常见处理是把 X 中心化：

\[
X_c=X-\bar X
\]

这样类别主效应表示“在平均 X 水平下的组别差异”，通常更容易沟通。中心化不会改变预测值，也不会删除交互，只会改变系数的基准点。

## R 中的公式语法

```r
model_additive <- lm(delivery_hours ~ distance_km + priority, data = delivery)
model_interaction <- lm(delivery_hours ~ distance_km * priority, data = delivery)
```

`x * group` 会展开为 `x + group + x:group`。如果只写 `x:group` 而不保留主效应，通常需要非常明确的理论理由。

## 分段模型与“把数值切成类别”

把连续变量 `cut()` 成多个区间可以得到阶梯式关系，但会丢失区间内部的顺序和精度，并且切点选择可能非常主观。

这种做法适合业务规则本来就是档位制，例如客户等级、费率档或服务 SLA 档，而不适合作为处理普通连续关系的默认办法。

如果真正需要分段线性关系，更合理的工具包括 spline、piecewise regression 或显式的 hinge function，而不是随意把连续变量切成三组。

## 模型比较要看“新增结构”是否值得

线性、二次和交互模型通常可以通过嵌套模型比较、信息准则或交叉验证来判断复杂度是否带来足够收益。

但“显著”仍不等同于“值得保留”。如果交互项统计显著却只改变极小幅度预测，而且令沟通成本大幅增加，业务场景可能更适合保留简洁模型。反过来，一个对关键高风险群体非常重要的交互，即使总体平均提升不大，也可能值得保留。

## 可视化比单独系数表更重要

对于非线性和交互模型，最好把预测关系画出来：横轴放 X，纵轴放预测 Y；不同组用不同线；必要时加置信带。这样可以直接看出：曲率在哪里发生、两组差异是否随 X 放大、模型是否在边缘做出不合理外推。

## 常见错误

- 看到残差弯曲就不断增加多项式次数。
- 使用高阶多项式后仍把 \(\beta_1\) 当作固定边际效应。
- 忘记类别变量的 reference level。
- 模型含交互却逐个解释主效应，不说明条件。
- 把连续变量任意分箱，只为了让图看起来更整齐。
- 只比较训练 R²，不看验证误差和边界行为。
- 在样本范围外使用高阶多项式做远距离外推。
