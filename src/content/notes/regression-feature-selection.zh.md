## 变量越多，训练结果通常越好看

在线性回归里，只要加入一个新的解释变量，训练集上的 SSE 不会增加，R² 也不会下降。于是，如果只按训练 R² 选模型，最复杂的那个几乎总能赢。

问题是，训练数据上的拟合更好，不代表模型真的更好。新变量可能只是记住了样本里的偶然波动，也可能让系数变得难解释、对新数据更不稳定。

特征选择真正要平衡的是三件事：信息、复杂度和泛化能力。

如果模型主要用来解释，变量的业务含义和系数稳定性很重要；如果模型主要用来预测，新数据上的误差通常更重要。两种目标会影响最后保留哪些变量。

## Adjusted R²给新增变量收一点“复杂度税”

普通 R² 只会随着变量增加而保持不变或上升。Adjusted R² 则在拟合收益之外考虑参数数量：

\[
\bar R^2=1-(1-R^2)\frac{n-1}{n-p-1}
\]

其中 n 是样本量，p 是解释变量数量。

如果新增变量带来的 R² 提升很小，惩罚项可能让 Adjusted R² 反而下降。这比直接看 R² 更适合比较复杂度不同的线性模型。

不过它的惩罚并不算强，而且仍然主要围绕样本内拟合。因此它适合做快速比较，不应该被当成唯一选择标准。

## BIC 更偏向简单模型

BIC，Bayesian Information Criterion，会同时考虑拟合和参数数量。常见形式可以写成：

\[
BIC=n\log\left(\frac{SSE}{n}\right)+k\log n
\]

其中 k 是参数数量。

BIC 越小越好。和 Adjusted R² 相比，它通常对复杂模型施加更强的惩罚，所以更容易选出变量较少的模型。

这在解释型分析中往往很有吸引力：如果两个模型拟合差不多，更简单的模型通常更容易沟通，也更不容易依赖样本噪声。

但 BIC 的“偏简单”并不保证预测一定最好。预测任务还是应该直接看样本外表现。

## 交叉验证直接问“新数据上会怎样”

Cross-validation，简称 CV，不再只看训练数据，而是反复把一部分数据留出来做验证。

K-fold CV 的基本过程是：

1. 把数据分成 K 份；
2. 用 K-1 份训练；
3. 用剩下 1 份计算验证误差；
4. 轮流让每一份做验证集；
5. 汇总 K 次误差。

如果目标是预测，CV 往往比“哪个变量显著”更贴近真正的问题：模型遇到没见过的数据时表现如何？

需要注意，CV 也有随机波动。尤其样本量不大时，最好使用固定随机种子或重复交叉验证，并比较误差差异是否真的有实际意义。

## 为什么逐步回归容易被过度相信

Forward selection、backward elimination 和 stepwise selection 都很常见。它们的优点是简单、自动，缺点也正来自这种自动化。

模型如果反复根据同一份样本的 p 值或信息准则挑变量，最终留下的系数和显著性会带有选择偏差。不同样本稍微变化，路径也可能完全不同。

逐步法可以作为探索工具，但不适合把最终结果包装成“唯一正确的模型”。如果业务上有必须保留的控制变量，也不应该让自动算法因为一次样本结果就随意删除。

## Ridge 不是删变量，而是把系数往回收

Ridge regression 在普通平方误差后面加上 L2 惩罚：

\[
\min_{\beta}\left[\sum_{i=1}^{n}(y_i-\hat y_i)^2+\lambda\sum_{j=1}^{p}\beta_j^2\right]
\]

\(\lambda\) 越大，系数被压缩得越强。

Ridge 特别适合变量很多、彼此相关较强的情况。它不会像普通 OLS 那样让共线变量的系数大幅摆动，而是把权重更平滑地分配出去。

代价是模型不再追求无偏的 OLS 系数，而是用一点 bias 换更低的 variance。对于预测任务，这种交换经常是值得的。

## Lasso 会把一部分系数压到零

Lasso 使用 L1 惩罚：

\[
\min_{\beta}\left[\sum_{i=1}^{n}(y_i-\hat y_i)^2+\lambda\sum_{j=1}^{p}|\beta_j|\right]
\]

它和 Ridge 最大的直观差别是：Lasso 可以把某些系数直接压成 0，因此同时完成收缩和变量选择。

这让模型看起来更稀疏，也更容易得到一个较短的变量清单。

但当一组预测变量高度相关时，Lasso 可能在它们之间挑一个留下、把其他压掉，而且这个选择可能随样本变化。因此“系数被压成 0”不等于该变量在业务上绝对没有价值。

## 正则化前通常需要标准化变量

Ridge 和 Lasso 的惩罚直接作用在系数大小上。如果一个变量用元计量，另一个用万元计量，原始尺度会影响惩罚力度。

因此，正则化模型通常会先标准化数值变量。`glmnet` 默认会做相应处理，但建模时仍然要清楚数据尺度发生了什么。

R 中可以使用：

```r
library(glmnet)

x <- model.matrix(y ~ ., data = df)[, -1]
y <- df$y

ridge_fit <- cv.glmnet(x, y, alpha = 0)
lasso_fit <- cv.glmnet(x, y, alpha = 1)
```

`alpha = 0` 是 Ridge，`alpha = 1` 是 Lasso。交叉验证通常用来选择 \(\lambda\)。

## PCR 和 PLS走的是另一条路

Principal Components Regression（PCR）不是直接删原始变量，而是先把高度相关的预测变量压缩成若干主成分，再用这些成分做回归。

它的优势是能处理高维和共线性，但主成分通常不如原始业务变量容易解释。

Partial Least Squares（PLS）也会构造新的低维成分，不过构造成分时会同时考虑 X 和 Y 的关系。和 PCR 相比，它更直接地把预测目标带入降维过程。

PCR 和 PLS 更适合变量很多、相关结构复杂的场景。对于只有几个清晰业务变量的普通回归，直接解释原始变量往往更自然。

## 解释模型和预测模型会选出不同答案

假设某个变量对预测误差帮助不大，但它是重要的混杂控制变量。解释型模型可能仍然需要保留它，因为删掉后其他系数的含义会改变。

反过来，一个变量很难给出因果或业务解释，却能稳定提高样本外预测。预测模型可能愿意留下它。

因此，变量选择前先回答“模型最终拿来做什么”非常重要。

```text
解释为主
→ 更关心变量含义、控制结构、系数稳定性

预测为主
→ 更关心 validation / CV loss 与泛化能力
```

同一组数据出现两个不同的最终模型，并不一定是谁做错了，可能只是目标不同。

## 不要把“显著变量”当成唯一候选集

用 p 值筛变量是最常见的做法之一，但它会忽略几个问题：

- p 值受样本量影响很大；
- 共线性会放大标准误；
- 某个控制变量即使不显著，也可能影响其他系数；
- 预测效果和统计显著性不是同一个目标。

一个更可靠的选择过程会同时看理论或业务理由、模型诊断、信息准则和样本外表现，而不是让一个阈值决定全部变量去留。

## 一套实用的模型选择流程

可以把过程压缩成下面几步：

1. 先定义目标：解释还是预测；
2. 根据业务和数据生成过程保留必要变量；
3. 检查共线性、异常点和明显的数据质量问题；
4. 用 Adjusted R²、BIC 等比较一组合理候选模型；
5. 如果目标偏预测，用 CV 比较样本外误差；
6. 变量多或共线性强时，再比较 Ridge、Lasso、PCR 或 PLS；
7. 最后检查结果是否稳定、是否还能解释。

特征选择并不是从几十个变量里“找出正确答案”，而是在信息、复杂度、稳定性和业务用途之间做取舍。一个更短的模型只有在它没有丢掉关键结构时，才是真的更好。
